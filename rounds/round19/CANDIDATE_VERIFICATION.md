# 候选密钥机械一致性验收

`verify_candidate.py` 验收用户提供的候选表，不搜索或生成密钥。通过只表示 **conditional_mechanical_consistency_only**：在明确读本、分组与 null 假设下，给定单表能覆盖全部输入音节，并经逆表精确重现输入。任意满足条件的人工单射表都可能通过，因此机械 roundtrip 不是历史真实性、独立验证或破译成功的证据。

## 模型与输入

- JSON 文件是非空对象：两个小写 ASCII 字母组成的一个 CV 音节 → `"00"` 至 `"99"` 的两位 ASCII 数字字符串，例如 `{"mu":"12","po":"34"}`。同一单表逐音节使用，`mu po` 拼为四位数字标签 `1234`，`mu mu` 拼为 `1212`。此例仅是人造测试格式，不是六月候选密钥。
- 检查全部提供的表项：键是否合法、值域是否合法、是否单射、是否有重复 JSON 键。允许未用到的表项，但也必须合法且不能与已用表项冲突。
- “完整覆盖”指所选读本的每个 CV 音节都有映射。工具不要求伪造未观察到的表项，也不证明历史上存在完整 100 项表。
- 采用 Round 19 的贪心 CV/VC 识别，`y` 的双角色规则沿用审计器。相位固定为零；去除假定 null 后，在同一份输入内连续以两个 CV 音节分组，允许跨词边界。
- 存在 VC 候选 null 时必须传 `--accept-vc-nulls`。所有 null 的原字串与位置都会保留；该选项表示接受假设，并不证明这些字母确为空码。
- 拒绝未解释字符、括号注记、残余单字符、末尾落单音节以及空密文；不静默跳过或截断。非 ASCII 密文字母不会通过 Unicode 小写归一化变成合法字母。

## 使用

只依赖 Python 标准库。脚本用自身路径寻找仓库输入，可从任意工作目录执行；下例中的绝对路径需换成实际克隆和候选文件路径。

```sh
python3 /path/to/repo/rounds/round19/verify_candidate.py \
  --mapping /path/to/candidate.json \
  --reading witness:1917-06-24_0509 \
  --accept-vc-nulls
```

`--reading` 必须明确选择 `raw_notes`、`program_variant`、`witness`、`R18_B`、`R18_D` 之一，加冒号和 `1917-06-24_0509` 或 `1917-06-29_0511`。实际冻结读本可能因未解释字符而被拒绝；这是验收结果，不能以跳过字符来“修复”。

选择 `R18_B` 或 `R18_D` 还必须加 `--accept-round18-emendations`，承认 Round 18 的校改假设。尤其 `R18_D` 不是未经改动的独立盲读。此开关不代表进行了新的图像核验。

自定义 UTF-8 文件可用 `--text-file /path/to/cipher.txt` 代替 `--reading`。文件字节按原样解码，不进行换行转换。自定义来源由调用者负责；把校改文字复制成自定义文件不会使其获得独立性。自定义文件没有自动识别或排除署名的功能。仓库 `raw_notes` 中预先明确声明的署名作为布局资料保留，不计入数字流。

默认 JSON 输出至标准输出；`--output /path/to/result.json` 可写入已存在的目录。成功返回 0，验收失败返回 1，命令行或输出路径错误返回 2。失败 JSON 含错误原因和位置（适用时），已读到的输入与表保留 SHA-256；文件不可读或读本尚未接受时不能提供相应输入哈希。

## 输出与证据边界

成功输出含原始表文件 SHA-256、排序规范化表 SHA-256、选定读本文本 SHA-256、逆向重建文本 SHA-256；仓库读本另带冻结来源文件哈希与来源说明。逐码列出四位数字值、两个音节各自的两位数字值、逆向码组、原音节跨度、词编号和跨词情况。`layout` 保留全部词、空白及署名，`candidate_null_locations` 保留所有 null。

逆向恢复的 CV 字母来自数字值经逆表查得的码组；大小写、null、空白、词边界及署名从显式布局旁信息恢复。数字流单独不能恢复这些信息。`exact_input_roundtrip` 因而只验证“数字流 + 所提供的布局旁信息”能回到所选输入，不能当作独立约束计分。

输出明确将 `historical_authentication`、`independent_validation` 设为 `false`。每音节两位数字拼为四位 CTC 标签，但不查汉字表；因此工具没有验证标签是否有对应历史电报码、没有中文语义评分，也没有跨信件的历史证据验收。若希望候选表同时解释多份读本，应对每份分别提供同一个候选 JSON，并核对同一 `mapping_file_sha256`；各次机械通过仍不构成独立历史验证。

## 回归测试

```sh
python3 -m unittest discover -s /path/to/repo/rounds/round19/tests -p 'test_verify_candidate.py' -v
```

正对照仅使用短人造密文与小型人工表，验证空白、大小写、null、跨词分组及哈希；负对照包括遗漏表项、重复值、重复键、非法值、非法键、非 ASCII 字符、注记、尾字符、尾音节、未接受假设与空输入。不会据此生成实际六月候选报告。
