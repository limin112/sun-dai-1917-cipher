六月电报已验证译文仍为 0 字。以下为原始报告全文，结论以更高轮次为准。

报告全文

研究日期：2026-10-12（Asia/Shanghai）。目标严格为 JACAR B03050090200 的 1917-06-24 0509（孙中山上海→戴季陶东京）与 1917-06-29 0511（戴季陶东京→孙中山上海）。仍没有可接受的六月中文译文（0字）、没有密钥；两封未解。 本轮从新来源获得了真正有用的底层新输入，且执行了新旧转录差异与分组对齐程序，不把已解1916年密电冒充本题。

1. 与 Round 15 相比最大的增量：找到并亲自目视检查了两张六月密电的公开原档扫描复制图

新增独立研究：Brice Dudout（与 Claude 合作）2026年10月发表的「破解文密」技术报告、公开电报页与可复现 GitHub 仓库。本次通过已经连接的 GitHub 实际取回图片的 Base64 数据，在视觉界面查看（不是只看缩略目录，更不是读网页猜原图）。在仓库中核对图片 blob SHA、取图并逐张目视：

  • 0509 完整扫描复制图：scan-0509-full.webp，GitHub blob SHA afb5a943b4f1caee1e917017312c5ee04c7355ea。图像清楚显示1917-06-24上海发电、东京收报、署名 Sunwen；第二组含不寻常的带变音符号的字母（作者指出是摩斯 ä）。
  • 0511 a+b 两页合并扫描复制图：scan-0511-full.webp，blob SHA 44ca9450a41b884dddfff994b70e61cc4cdb6a83。图像可以看到 1917-06-29 东京发送、上海收报、尾签 Tai，且有涂改和笔迹混淆。

2. 关键纠偏：两封1917六月电报并没有写明「文密」前缀

Dudout 真正恢复了1916年另两条线路的G0与Y0两把历史密钥；其中东京→肇庆一路有明文的 文密（数字 2429 1378）前缀，东京↔云南另一路是 Cg。独立研究者明确记录：1917年0509与0511两封电报上既无文密，也无Cg，且两把1916年的G0/Y0均不能译出它们。因此过去以「文密」称呼这两封六月电报只宜作为工作标签／研究者的分类假设，不得把1916同名密钥直接认定是六月密钥。1916年的突破确实可作方法正对照（公开规则、证实该年代存在这种机制），但绝不是本题成果。

独立技术报告已尝试十多万乃至二十多万历史表、任意坐标搜索、42个可能词锚点，仍未破译六月。我们没有重复这类大规模重复负面搜索。

3. 0509 的进展：老数据“9字母短词”在独立重读中变成完整10字母；总长80字母

先前冻结分析输入：第2组 vemucayri（9字母），第3组 mevecafema（10字母，另有可选u），另有第4组和第8组笔迹分歧。独立读者 Brice 所公开的 0509 原始盲读为8组、每组10字母：

lidajysamy vemucicyri mevecafemu
pokelubazi riyecafafi cymefymeca
madamymiri pujihohehe

相对于原先分析版本，8组里4组的读法改变；总计80字母=40个二字母槽=在两槽一字模式下20个潜在字符（最后一层仅是结构条件，不代表已成功还原20字）。双角色 y（y 可元音也可辅音）的语法检查：旧完整词35/35对有效，独立重读全8词 40/40对有效。这是从不同读者、同一历史扫描来源得到的可解释度提升；不等于恢复数字表。

不能立即将旧第2组“修成”唯一答案。 新重读 vemucicyri 与作者注明的 vemucekyri（把扫描中的摩斯 ä 解释为 e+k）都通过简单语法检查。视觉上确有非常规变音符/笔迹问题，但不保证任一具体拉丁字母串无误；这两个各自保存在说明而非悄然取代原记录。它不是上一轮所设想的随意“补一个字母”：须回到原电报的通信和转写规则。

4. 0511 的进展：原先唯一ee异常不再稳固；但新转录并非完全规则

独立重读的0511分为 a（18组）和 b（11组），合计29组，282个拉丁字母（141个双字母槽）。长度有11字母1组、9字母1组、10字母23组、8字母4组。一长一短恰好平衡至偶数，但绝不擅自调剂或删除。与旧冻结分析版本29组相比，有16组读法变化。

最有价值的纠偏： Round14认为唯一违反元辅配对的 kohokycuee 结尾 ee；新发表的盲读及所查看扫描复制图更支持 kohokycuce，末尾是 ce（可合法组成音节），并非可靠的ee。该词的语法异常随之消失。新重读但有另一组 damowmhosy，第3个双字符是 wm，它不符合原简单双角色语法；早期材料的 damoumhosy 读成 um 则符合。前者与后者只有读法分歧，不能按想要的统计结果决定选哪个。

程序对字母的真实统计（按原规则保留异长词）如下：

0511 处理方式 双字母组数 y双角色合法 不合法 保留的长度异常
旧冻结、各词独立 141 140 ee（旧第7词） 无奇数词（旧程序将多处不确定长度正则化）
独立重读、各词独立且每奇数词孤立尾字 140 139 wm（第12词） 第1词11字母、第3词9字母，各留单字尾
独立重读、整封连续配对（仅作边界敏感性） 141 138 oa、sd、wm 无尾字，但跨词配对是附加假设

这说明 Round14 的“175/176对”是特定冻结旧转录下的结构事实，不是原件的唯一规则。独立重读变化后，“ee可能只是旧抄录问题”成为强烈值得核对的线索，同时更多异长与倒装片段限制了纯字母语法的解释力。不能把新资料说成全部更好，更不能自动把两份转录合成“最合规则”的密文。

5. 新执行的4字母重合核对：出现与电报词界不同步的重复结构

只使用独立重读，尝试传统“2个双字母槽合成一个4字母电码”的必要条件，不查中国字、不拟合密钥。按 0509 从字符0起，0511a 从字符0起，0511b 从字符2起的事后提示相位查对齐四元组：

  • cafe：0509 一次，0511a 一次（跨两个10字母电报词的接缝），0511b 一次；合计三处。
  • kige：0511a 一次，0511b 一次；合计两处。
  • mafy：0511b 两次，其中一次跨相邻10字母电报词的接缝。这能提醒以后不能把10字母词界当作中文单字边界。
  • fojy：0511b独立重读仅一次；若有条件地把第8词的 fogylisicy 读作作者注明的疑读 fojylisicy（g/j易混），则与另一处共两次，且相位对齐。这是明列的敏感性候选，不是原文校定，也不能因为重复而强行替换字母。

在两个已知不同日期的电报里出现同一个4字母片段，符合常见代码重复的直觉，但也可能来自语法/编码机制；没有密码表就不知道这些组是什么汉字，不能把“常见字”强行映射给它们。而三个片段的对齐是在看过数据后选出来的，不能把它当成独立显著性检验。round16_analysis.py 保存了每个出现位置、是否跨词界、所用相位及替代读法的条件变化。

7. 后续最有价值的动作

本轮首次获得可亲自目视的0509/0511扫描复制图片。接下来不再把“拿不到图”当作永久障碍，而是围绕真实图上不清楚的几处笔迹展开：0509第2组的 ä 摩斯解释，0511第7组的 ce/ee，0511第12组 wm/um，0511a开头11+9不等长和突兀的 oas、liriopen 等。从已读的其它档案寻找同密钥的更多密文、真正相同发收人的明密对照或具体私人密码本，不要在原数据未知条件下重复任意表拟合。已取得戴季陶1928回忆所述六月致孙中山的报告线索仍要追，但不是这两份电报已经破译的证据。

目前结论：六月原图访问问题取得实质性改善（非JACAR raw，本轮核查了公开副本），公开独立重读修正了关键输入和字符位数；新的4字母对齐位置可复算。可是密码体系与六月明文仍未破解，0字，必须继续。
